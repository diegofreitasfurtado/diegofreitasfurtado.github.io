# Receitas das 3 variantes de post

Detalhe expandido das variantes A, B, C para a `tese-to-content`.

## Por que 3 variantes (e não uma só)

O Workflow de 7 dias do Diego pede 3 ângulos do mesmo argumento, para que ele escolha o que mais ressoa naquela semana. Cada variante optimiza para uma reação diferente:

- **A (História pessoal):** mais comentários ("também me aconteceu…")
- **B (Tese contraintuitiva):** mais reposts e debate
- **C (Framework prático):** mais saves e mensagens privadas

Se o Diego só pedir uma, sugere saber qual ele quer **antes** de gerar.

## Variante A — História pessoal

### Estrutura

```
[1] Momento concreto, em primeira pessoa, com data/lugar/cena
    (1-2 frases, sensorial)

[2] Tensão ou observação que o momento revelou
    (2-3 frases)

[3] Conexão à Tese (`Argumento central`)
    (1-2 frases)

[4] Reflexão final, sem moral explícita
    (1 frase)
```

### Constraints

- **Não inventa o momento.** Se o Diego não forneceu cena, a skill **para e pede**:
  > *"A variante A precisa de um momento concreto. Tens uma cena recente onde esta Tese se manifestou? (cliente, projeto, conversa, observação no metro, etc.)"*

### Exemplo (Tese fictícia: "Automação não é luxo, é higiene")

> Sexta passada, vi a equipa de Vendas a copiar dados manualmente entre 3 planilhas pelo terceiro mês seguido.
>
> Não era falta de ferramenta — Power BI estava lá. Era hábito de não confiar em automação porque "no mês passado deu erro".
>
> Aqui está a coisa: automação não é luxo de empresa madura. É higiene operacional. Você não escolhe entre fazer manual ou automatizar — escolhe entre treinar a equipa para confiar em pipelines, ou pagar 30 horas por mês em retrabalho até alguém se demitir.
>
> O custo da automação não é o script. É o atrito de mudar a relação das pessoas com a confiança no sistema.

## Variante B — Tese contraintuitiva

### Estrutura

```
[1] "A maioria faz X." (o que a maioria faz da Tese, 1 frase)

[2] "Eu defendo Y." (o que defendo, 1 frase)

[3] "Aqui o porquê:" (3 razões, bullets)
    - Razão 1 (factual)
    - Razão 2 (consequência prática)
    - Razão 3 (princípio)

[4] Fechamento provocativo (1 frase)
```

### Constraints

- Cola **literalmente** os campos da Tese (`O que a maioria faz`, `O que defendo`, `Por quê`)
- Os bullets devem ser concretos, não filosóficos
- Fechamento pode ser pergunta retórica, mas sem pedido de "comente abaixo"

### Exemplo

> A maioria das equipas de dados começa um projeto pelo dashboard.
>
> Eu defendo o oposto: comece pelo glossário.
>
> Aqui o porquê:
> — Se "receita" significa coisa diferente para Vendas e Finanças, nenhum gráfico vai resolver. Vai amplificar.
> — KPIs sem definição partilhada são opinião com cores bonitas.
> — Quem alinha vocabulário primeiro entrega métrica que aguenta auditoria. Quem entrega visual primeiro vai rever tudo no Q2.
>
> Dashboards são a parte fácil. A parte difícil é decidir o que estamos a contar.

## Variante C — Framework prático

### Estrutura

```
[1] Promessa concreta (1 frase com verbo de ação)

[2] "Como [verbo]:" ou "5 passos para [resultado]:"

[3] Lista numerada (3-5 passos)
    1. [verbo + objeto curto]
       (1 frase explicativa)
    2. [...]
    ...

[4] Fechamento que conecta de volta à Tese (1 frase)
```

### Constraints

- Passos devem ser **acionáveis em 24h** (não "estude X durante 3 meses")
- Verbos no imperativo
- Sem mais de 5 passos (preferência: 3 ou 4)

### Exemplo

> Como mapear processos antes de automatizar.
>
> 5 passos que economizam meses de retrabalho:
>
> 1. **Pergunte quem usa o output, não quem produz o input.** O dono do processo é quem precisa do resultado.
>
> 2. **Desenhe o fluxo a lápis primeiro.** Se não cabe numa folha, está cedo demais para automatizar.
>
> 3. **Identifique as 3 decisões críticas.** Onde a pessoa pára para pensar — não onde clica.
>
> 4. **Escreva os critérios dessas decisões em texto.** Não em fluxograma.
>
> 5. **Só depois disso, abra o editor de pipelines.**
>
> Automação que pula esses passos não substitui o trabalho — repassa o erro com mais velocidade.

## Adaptação ao tom do Diego

Diego comunica com:

- **Densidade:** prefere afirmações fortes, sem amaciar com "talvez", "às vezes", "no meu humilde entender"
- **Especificidade:** sempre concreto, com números/lugares/cenas
- **Crítica construtiva:** aponta o erro mas oferece alternativa
- **Sem clichês:** evita "no fim do dia", "ao final das contas", "é uma jornada"

Se uma variante começar a soar genérica, **rejeita e refaz** antes de mostrar.
